# ONLY US 실행과 운영 설정

Node.js 22 이상을 사용합니다. 로컬 개발은 `npm ci` 후 `npm run dev`로 실행하고, 공개 환경은 `npm run build` 후 `npm run start`로 실행합니다. `next dev`의 초기 컴파일 시간을 운영 환경 로딩 시간으로 판단하지 않습니다.

## 배포 환경

- `.env.example`를 기준으로 환경 변수를 설정합니다. 실제 키가 있는 `.env.local`은 저장소에 올리지 않습니다.
- `NEXT_PUBLIC_SITE_URL`은 실제 HTTPS 도메인으로 설정합니다. Supabase Authentication의 Site URL과 허용 Redirect URL에도 같은 도메인의 `/auth/callback`을 등록합니다.
- 회원가입은 Supabase의 이메일 확인 설정을 따릅니다. 확인이 필요한 프로젝트에서는 인증 이메일을 받을 수 있어야 하며, 발신 설정과 실제 인증 링크를 함께 확인합니다.
- 운영 Auth 설정에서 유출 비밀번호 보호 기능을 사용할 수 있는지도 확인합니다. 이번 DB 검수에서 해당 보호가 꺼져 있는 것으로 확인됐으며, SQL 복구와는 별도의 서비스 설정입니다.
- Supabase secret/service role, Kakao REST, AI, 관광 API 키는 서버에만 설정합니다. 브라우저용 지도 키의 허용 도메인은 운영 도메인과 일치시킵니다.
- 처음 만든 DB에는 `supabase/migrations`의 전체 SQL을 파일명 순서로 적용합니다. 기존 DB는 마이그레이션 이력과 백업을 확인하고 누락된 파일만 적용합니다. 과거 데모 정리 SQL을 기존 데이터에 임의로 재실행하지 않습니다.
- `save_couple_plan_atomic` RPC는 일정 교체와 수정 충돌 검사의 필수 조건입니다. 사용할 수 없으면 앱은 기존 데이터를 유지하고 저장 오류를 표시합니다.
- Realtime publication에는 `activities`, `memory_wall_boards`가 포함되어야 합니다. 앱은 커플별 공유 채널을 사용하고, 연결 복구·탭 복귀·주기적 조회로 누락된 변경을 보완합니다.
- 사진 버킷 `memory-photos`는 private으로 유지합니다. 사진 URL은 소유권 검사 후 제한된 기간 동안 서명합니다.

## 이번 DB 복구

연결된 프로젝트에는 `20261010210139_restore_workspace_sync.sql`을 적용하고 카탈로그 조회로 검증했습니다. 다른 환경에서는 해당 환경의 마이그레이션 이력과 스키마를 확인한 뒤 적용합니다.

- `activities` 실시간 publication, 수정·삭제 정책과 replica identity를 복구했습니다.
- 누락된 `plan_items.lng/lat` 컬럼과 좌표를 저장하는 원자적 일정 RPC를 복구했습니다.
- 장소·활동·초대 조회 인덱스 3개와 인증 ID를 한 번 계산하는 RLS 정책을 적용했습니다.
- 장소 선호 수정 시 대상 커플도 검사하며, 데모 삽입 함수의 외부 실행 권한을 회수했습니다. 새 공간 생성 시 자동 데모 삽입을 제거했습니다.
- 초대 수락은 자기 초대를 거부하고 대상 커플을 잠가 서로 다른 초대의 동시 수락도 2명 제한을 지킵니다.

이 복구는 스키마·정책·함수 정의를 변경했습니다. 실제 사용자 일정·사진·장소를 저장하거나 삭제하는 검증은 실행하지 않았습니다.

## 추가 감사와 데이터 보호

연결된 프로젝트에 다음 파일을 추가 적용하고 함수 권한·RLS·마이그레이션 이력을 조회해 확인했습니다.

- `20261011033647_restore_date_drafts.sql`: 빠져 있던 날짜별 일정 테이블을 복구하고, 기존 활동에 남아 있는 최신 일정 초안을 보존해 이관합니다. 삭제 표시가 있는 날짜와 잘못된 날짜는 복구하지 않습니다.
- `20261011033654_protect_invite_workspace.sql`: 개인 공간에 기록이 있으면 초대 수락을 중단합니다. 기존 공간을 삭제하지 않으며, 동시 수락과 재시도에도 회원 수와 기록을 보호합니다. 기록이 있는 사용자는 자신의 공간에서 만든 초대를 상대에게 공유할 수 있습니다. 서로 다른 두 공간의 기록을 합치는 기능은 제공하지 않습니다.
- `20261011033700_add_atomic_partner_disconnect.sql`: 연결 해제·새 개인 공간 생성·활동 기록을 한 트랜잭션으로 처리합니다. 상대의 공간과 기존 기록은 보존됩니다. 필수 함수가 없으면 앱에서 연결 해제를 중단합니다.
- `20261011033705_atomic_memory_creation.sql`: 추억 본문·사진·활동·알림 대기를 한 트랜잭션으로 저장합니다. 응답이 끊겨도 같은 저장 ID로 확인하여 새 추억이 중복되지 않습니다.
- `20261011034904_restore_trusted_place_cache.sql`: 누락된 공용 장소 정보 캐시를 복구했습니다. 로그인 사용자는 조회만 하고 신뢰된 서버만 기록합니다. 캐시 저장은 응답 이후에 실행하여 화면 응답을 지연시키지 않습니다.
- `20261011035107_atomic_memory_update.sql`: 추억 수정도 본문·추가 사진·활동·저장 요청 기록을 한 번에 처리합니다. 사진만 추가한 요청도 재시도 시 중복되지 않으며, 이미 저장된 요청은 파트너의 후속 변경을 포함한 현재 결과를 반환합니다.
- `20261011035731_tighten_function_access_and_foreign_keys.sql`: 인증 내부 함수의 불필요한 익명 실행과 회원가입 트리거의 직접 실행 권한을 회수하고, 누락된 외래키 조회 인덱스 13개를 추가했습니다. 가입 트리거와 로그인 사용자의 멤버십 검사는 계속 동작합니다.

로그인·복구·연결 해제 때 장소 이름이나 좌표로 실제 기록을 추정해 삭제하던 자동 데모 정리를 제거했습니다. 예전 데모 문구를 사용한 실제 여행 일정도 보존합니다. 자정을 넘겨 새 장소를 추가할 때 같은 날짜의 오전 일정으로 돌아가지 않도록 안내합니다.

보관함·선물·버킷리스트 저장은 작성한 내용이 같으면 재시도 ID를 유지합니다. 중복 ID는 기존 항목을 수정하지 않고 현재 저장된 결과를 반환하므로 파트너가 변경한 내용도 유지합니다. 스크린샷에서 추출한 여러 항목도 같은 방식으로 저장합니다.

AI 서버 함수는 로그인과 공간 준비 상태를 확인합니다. 기존 OpenAI 키 설정을 유지하며 유료 호출 없이 모의 응답으로 접근 제어·오류 회복·늦게 도착한 응답 처리를 검증했습니다. 사진 분석 도중 삭제하거나 닫은 입력의 분석 결과는 새 작성 화면에 반영하지 않습니다. 추억의 수동 지도 위치는 연결된 장소 좌표보다 우선하며 잘못된 좌표는 업로드 전에 안내합니다.

위 재시도·충돌·권한 검증은 자동 테스트와 별도 로컬 PostgreSQL 실행 환경의 가상 계정·가상 기록으로 진행했습니다. 날짜 초안 이관은 기존 내용을 보존하는 데이터 복구 작업입니다.

브라우저 검증 중 추억 작성의 단계 이동 버튼이 저장 버튼으로 바뀌면서 기본 클릭 동작으로 빈 기록 한 건이 저장되는 오류를 발견했습니다. 단계 이동에서 기본 동작을 취소하고 단계별 DOM을 구분하며 첫 단계의 제출을 차단했습니다. 검증 중 생성된 빈 기록은 정확한 ID·생성 시각·빈 필드·사진 없음 조건을 확인한 뒤 해당 활동과 아직 발송되지 않은 대기 알림까지 한 트랜잭션으로 정리했습니다. 기존 기록은 변경하지 않았습니다.

작성창과 모바일 전체 메뉴는 열릴 때 내부로 키보드 포커스를 이동하고, Tab 이동을 내부에 유지하며, Esc로 닫은 뒤 원래 버튼으로 돌려보냅니다. 저장 중에는 닫기를 차단하고, 저장 결과가 불확실한 추억 수정은 재확인하기 전 입력과 닫기를 잠가 동일한 저장 요청을 보존합니다.

## AI 대화와 추가 기능 검수

기존 OpenAI 키와 모델 설정을 유지했습니다. OpenAI 통신 계층의 서버 전용 경계를 분리했고, 취향 점수 계산만 브라우저가 사용할 수 있는 순수 모듈로 옮겼습니다. 인증 정보나 서버 호출 모듈을 취향 화면 번들에 포함하지 않습니다.

- 한글 조합 중 Enter, 빈 전송, 연속 전송·적용·저장은 AI 호출이나 저장을 중복 실행하지 않습니다. 실패한 요청은 입력을 보존합니다. 과거 질문의 선택지는 현재 질문에 적용되지 않습니다.
- 날짜가 바뀌거나 수정 중 일정이 달라지면 오래된 응답·변경안을 폐기합니다. 여행의 빈 일차는 다른 일차의 전체 항목을 수정 대상으로 보내지 않습니다.
- 여행 화면의 새 요청은 기간을 모르면 먼저 묻습니다. 이미 선택한 당일·숙박 기간은 후속 요청에서도 유지합니다. 여러 날 코스는 하루 데이트로 저장하지 않습니다.
- 후보 세션 서명은 사용자 ID와 커플 ID도 포함합니다. 다른 계정·공간의 서명과 기존 범위 없는 서명은 인증된 요청에 재사용할 수 없습니다.
- 일정 방문 시간·체류 시간은 알려진 일정에서 답합니다. 매장 영업시간과 구분하며, 없는 장소 번호와 모호한 변경 대상은 재확인합니다. 명시된 번호 삭제·순서는 모델 재해석 없이 처리하고, 모델이 제안한 삭제 대상도 사용자 지시와 비교합니다.
- 실행하지 않은 예약·결제·저장·일정 변경 완료 답변, 문자열이 아닌 제안 버튼, 불완전한 변경 순서, 잘못된 후보 상태를 거부합니다. 사용자나 상대방의 부정적인 저장 장소 선호도는 일정 옵션에서 제외합니다.
- 유효한 JSON이어도 거절·잘린 응답·완료되지 않은 응답을 성공으로 처리하지 않습니다. 등록되지 않은 도구와 잘못된 인수는 실행하지 않습니다. 외부 요청과 응답 본문 읽기에 같은 제한 시간을 적용하며, 예약 이미지 분석 취소를 외부 요청에도 전달합니다.
- 여러 날 일정의 검증된 이동 시간은 전체 경로의 올바른 구간을 사용합니다. 특정 장소 시간 변경은 그 날짜의 후속 장소에만 적용합니다. 자정을 넘겨 같은 날짜의 오전 일정으로 표시되는 옵션은 반환하지 않습니다.
- 예약 스크린샷은 업로드 본문을 제한하고 실제 JPEG·PNG·WebP를 로컬에서 디코딩합니다. 4MB·2천만 픽셀·가로/세로 8192 제한과 손상·형식 위장 검사를 통과한 파일만 AI로 보냅니다. 예약의 상세 정보가 다른 항목은 같은 제목·코드라도 합치지 않습니다.
- 상품 링크의 인용부호·숫자 HTML 엔티티·상대 이미지 주소를 처리합니다. 이미지 주소도 공개 웹 주소인지 확인합니다. 검색은 띄어쓰기와 유니코드를 정규화하고 여러 검색어를 함께 찾습니다.
- 취향·메모 수정·삭제·정렬의 본 저장이 성공한 뒤 활동 기록이 실패해도 저장 성공을 보존합니다. OAuth 통신 실패는 로그인 또는 공간 복구 화면으로 이동합니다.

이번 검수의 최종 자동 검증은 1,602개 통과, 외부 서비스 전용 12개 건너뜀입니다. 타입 검사, 운영 빌드, 의존성 감사(취약점 0개)가 통과했습니다. AI 회귀 검증은 모의 응답·로컬 이미지·가상 DB 응답으로 실행했으며 실제 유료 모델의 자유 대화 품질 평가와 운영 두 계정 상호 변경 검증은 이 수치에 포함하지 않습니다.

최종 운영 빌드의 브라우저에서도 데이트 AI 패널 표시와 빈 Enter 전송 차단을 확인했습니다. 유료 모델 호출과 실제 기록 저장은 실행하지 않았습니다.

## 장소 탐색과 데이트 엔진 추가 검수

2026-10-11의 추가 수정은 장소 선택 → 서명된 후보 전달 → AI 코스 생성 → 시간·동선 검증 → 후속 대화 흐름을 대상으로 합니다.

- 화면의 4·6·8·12곳 선택 상한과 서버의 조용한 선택 잘림을 제거했습니다. 선택 수는 `선택한 장소 N곳`으로 표시합니다. 선택한 장소를 세션 기록 정리 때도 보존하며, 모델에는 모든 선택 ID를 전달합니다. 요청 본문의 용량·형식 검사는 계속 적용합니다. 현재 전체 일정 생성의 기간 지원 범위는 최대 6박 7일이며, 기간을 임의로 줄이지 않고 화면에서 안내합니다.
- `야경` 관심사를 전체 여행의 밤 시간대로 바꾸거나 `조용한`을 좁은 검색 반경으로 바꾸던 추정을 차단했습니다. 사용자가 말한 기간·시간·제외 음식·장소와 후속 수정 내용을 우선합니다.
- 일반 대화 모델 설정은 유지합니다. 검색 지원이 없는 대화 모델을 검색에 재사용하던 경로는 별도 검색 모델 `gpt-4.1-mini`로 연결했습니다. 기존 키로 모델 목록 GET 조회가 성공하고 두 모델이 계정 목록에 있는 것을 확인했습니다. 모델 목록 조회는 실제 생성·검색 품질 평가와 다릅니다.
- 장소 카드는 세부 업종, 실제 검색 지역·선택 조건, 확보된 관찰 근거와 출처를 함께 표시합니다. 식당·야경 후보도 기본 근거 조사 대상에 포함하며, 산 지번 주소의 동일 지점 판정을 복구했습니다. 미확인 야간 개방·주차·가격을 사실처럼 표시하지 않습니다.

이 결과를 바탕으로 선택한 모든 장소와 모든 일차를 하나의 완결된 여행 코스로 반환하도록 요청·스키마를 강화했습니다. 하루별 응답의 결합은 중복 없이 모든 선택 장소와 요청 일차를 정확히 충족할 때만 허용합니다. 야경 관심사가 있는 전망·야경 장소에는 18시 이후 방문 조건을 적용하며, 실제 일몰·야간 개방·접근 가능 여부는 확인 대상으로 안내합니다. 검증된 공연 시작 시간은 여러 공연에서도 고정하고 실제 이동·입장 준비 시간과 일반 장소의 최소 체류 시간을 함께 검사합니다. 영업시간 조건도 앞선 대화에서 유지하고 명시적인 조건 해제만 반영합니다.

추가 유료 호출 없이 실제 검색된 부산 장소 10곳으로 일정 배정을 재실행했습니다. 선택 10곳이 모두 3일에 포함됐고 야경 3곳은 각각 18시에 배정됐습니다. 이 재실행은 대체 일정 엔진 검증이며, 수정 후 실제 모델 생성의 재검증은 아닙니다. 이 추가 검수에서는 실제 사용자 일정 저장이나 DB 변경을 실행하지 않았습니다. 승인된 유료 호출 3회는 모두 사용했습니다.

## 데이트 엔진 고도화 및 예산 기능 제거

2026-10-11의 후속 검수에서 데이트·여행 생성과 수정, 취향 비교, 장소 탐색의 예산 기능을 제거했습니다. 예산 입력·합계·초과 차단·가성비 코스와 비용을 기준으로 한 후보 제외·순위는 사용하지 않습니다. 예산 없이 취향을 작성하고 저장할 수 있으며 과거 예산 값은 추천에 반영되지 않습니다. 기존 DB의 필수 열과 저장 기록은 호환 목적으로 유지합니다. 메뉴·입장료 등 실제 가격을 묻는 장소 질문은 예산 관리와 별개인 사실 확인으로 처리합니다.

- 지역 교체의 부정 표현, 여러 음식의 제외·해제, 방문 날짜와 부분 시간 변경, 변경된 여행 기간을 구분합니다. 지역을 바꿀 때 이전 지역의 고정 장소를 계속 강제하지 않습니다. 공연의 회차 시간은 하루 전체의 시작 시간으로 재해석하지 않습니다.
- 선택한 장소 전부의 최소 체류 시간이 도착·귀가 시간을 적용한 전체 시간보다 긴 경우 생성 전에 구체적으로 안내합니다. 확정된 공연에는 유효한 방문 날짜가 필요하며, 확인된 공연 소요 시간은 일반 장소처럼 임의로 줄이지 않습니다.
- 출처에서 확인된 영업시간·휴무·브레이크타임·마지막 주문·입장과 일차별 도착·출발 시간을 일정에 적용합니다. 명시한 공연 회차, 야경 시간, 이동·입장 준비 시간도 함께 검사합니다. 자료가 없는 운영 정보는 확인된 사실로 취급하지 않습니다.
- 코스 설계 단계의 근거 조사·공략집 검색·생성·수정·보행 경로는 `DATE_ENGINE_DESIGN_TIMEOUT_MS` 제한 시간을 공유합니다. 기본값은 45초이며 5~60초 범위를 허용합니다. 구조·동선 실패에 대한 모델 재요청은 합쳐서 최대 한 번입니다. 이 설정은 앞선 대화 해석·후보 검색을 포함한 전체 HTTP 요청 시간의 보장은 아닙니다.
- 공략집 검색의 동시 질의 임베딩과 동일 보행 요청을 공유합니다. 응답 본문 지연도 제한 시간으로 종료하고, 한 사용자의 취소가 다른 요청을 취소하지 않도록 분리합니다. 남은 시간이 없으면 뒤늦은 모델 요청을 시작하지 않습니다.
- 후보가 한 곳뿐이거나 선호 장소 수보다 적어도 가능한 대체 일정을 잃지 않습니다. ‘저녁 바꿔줘. 카페 주차 돼?’ 같은 복합 요청에서는 변경 대상과 장소 질문을 분리합니다. 새 교체·추가 후보가 없으면 기존 코스를 유지하고 독립적인 질문은 답할 수 있게 합니다.
- 선택·조건 변경 후 예전 저장 완료 표시를 제거하고 오래된 변경안의 저장을 막습니다. 조건을 바꾸거나 요청이 실패했을 때 선택·입력 내용이 조용히 사라지지 않도록 검증했습니다.

최종 자동 테스트는 1,903개 통과, 외부 서비스 전용 12개 건너뜀이며 타입 검사와 운영 빌드가 통과했습니다. 추가 유료 API 호출과 실제 사용자 일정 저장·운영 DB 변경은 실행하지 않았습니다. 실제 모델의 자유 대화·수정 후 코스 생성 품질 및 두 계정의 상호 변경은 모의 테스트 통과와 별도로 검증해야 합니다.

새 운영 빌드로 로컬 서버를 재시작했습니다. 로그인한 브라우저에서 기존 취향 불러오기, 장소·하루·음식 세 입력 단계의 예산 항목 제거, 데이트 AI 초기 안내와 빈 Enter 전송 차단을 확인했습니다. 최종 데이트 화면의 경고·오류 로그는 없었습니다. 취향과 일정의 실제 저장은 실행하지 않았습니다.
