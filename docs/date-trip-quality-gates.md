# 데이트·여행 추천 품질 게이트

## 2026-09-26 Date AI v2 적용 범위

- 기존 `AIPlannerState`, Playbook, 카카오 장소 검색, KOPIS 행사 확인, 장소 근거 저장소, 보행 경로 계산을 재사용한다. 의도는 하드 제약과 목표·소프트 선호·추론 근거로 분리하고, 저장된 취향은 필수 활동으로 승격하지 않는다.
- Playbook 40개에 512차원 임베딩을 저장하고 Supabase `match_date_playbook` RPC로 단계별 의미 검색을 한다. 우선순위와 태그는 메타데이터 신호로 남긴다. 모델 또는 DB가 응답하지 않으면 기존 로컬 Playbook 선택으로 돌아간다.
- 기본 검색 뒤 후보 역할이 부족하거나 조용함·사진·새로움 같은 강한 선호가 있으면 모델이 허용된 지역의 추가 장소 검색을 최대 두 차례 선택한다. 후보 장소의 지점별 근거, 알려진 음식 금지·비용, 코스 순서·동선·시간을 검증하고 실패한 모델 초안은 한 차례 수리한다.
- 실제 DB에서 40/40개 임베딩을 확인했고 사진·조용한 데이트 요청에서 의미 검색이 해당 규칙을 선택했다. 로컬 테스트 464개와 프로덕션 빌드, 기존 왕십리 라이브 코스 회귀 한 건이 통과했다. 이는 다지역 추천 품질이나 모델 성공률을 증명하지 않는다.
- 실시간 날씨·영업시간·예약 가능 여부와 대중교통 이동은 검증 공급자가 아직 없다. 장기 취향은 기존 프로필·저장 장소·지난 코스에 근거하며, 별도 부부 취향 학습 모델은 없다. 이 사실들은 확인 전까지 응답에서 확정할 수 없다.

## 4·13·14번 실행 엔진 고도화

- OpenAI 함수 호출로 `search_places`, `verify_performance`, `get_place_details`를 선택한다. 함수 인자는 허용 지역·검색어 길이·실제 검색된 장소 ID로 검증한 뒤 카카오 검색, KOPIS 회차 확인, 저장된 장소 상세 캐시에 연결한다. 도구 결과의 후보 증가·공연 확인·새 상세 정보 여부를 다음 모델 판단에 돌려준다. 2회·8호출을 기본 상한으로 둔다.
- 코스 설계 뒤 결정적 검증기가 하드 제약, 실제 보행 거리, 장소별 체류와 이동 시간 충돌을 검사한다. 경로가 확인된 대안이 모두 실패하면 실패 이유와 실제 이동 거리·시간을 모델에 전달해 다른 코스를 한 번 만든다.
- 그래도 코스가 없으면 상위 오케스트레이터가 검증 사유에 맞는 장소 검색을 최대 3회 호출하고, 새 지점이 생긴 경우에만 코스를 한 번 더 설계한다. 알레르기 안전성 미확인은 검색 결과만으로 해소했다고 취급하지 않는다. 단계별 호출·재시도·검증 문제 수는 원문 없는 진단 로그로 남긴다.
- 현 구현의 도구 범위는 장소 검색, 저장된 상세 정보, KOPIS 공연 확인이다. 날씨·영업시간·예약·대중교통을 실시간 검증하는 도구는 아직 없으므로 해당 항목을 확인된 사실로 말하지 않는다. 공개 Open-Meteo 무료 API는 상업적 사용에 별도 계약이 필요해 바로 연결하지 않았다. 이 범위는 4·13·14번의 실행 기반이며 완전한 범용 Date Agent 검증을 뜻하지 않는다.

## 남은 항목 고도화 (2026-09-26)

- 목표 해석에 식사 중요도와 도보 허용도를 추가했다. 명시한 음식 금지와 필수 활동은 하드 제약으로, 대화에서 추론한 분위기와 활동 강도는 소프트 점수로 유지한다.
- 검색 결과를 `DateCandidateRecord`로 묶어 지점 ID, 장소 사실, 속성별 근거, 점수 구성 요소, 제외 사유를 남긴다. 중복 지점을 합치고 알려진 제외 음식·개별 장소 예산 초과·공연 날짜 불일치를 코스 생성 전에 제거한다.
- 장소 점수는 취향·장소 품질·근거·과거 반응·새로움을 분리한다. 코스 점수는 이동, 경험 흐름, 일정 가능성, 여유를 별도로 평가한다. 명시한 제약 위반은 점수로 상쇄되지 않는다.
- 저장된 취향 프로필과 지난 데이트 기록을 재사용한다. “좋았지만 붐볐다”는 좋음과 혼잡을 별도 사건으로 보존하며, 추론 반응은 같은 장소의 순위에만 가감한다. 명시 선호와 추론 신호는 구분한다.
- 첫 데이트, 함께 만드는 활동, 기념일 정책을 Playbook에 추가해 43개 카드와 임베딩을 동기화했다. 지역과 숙박 기간 외의 선택 질문은 기본 제안을 만들 수 있으면 생략한다.
- 날씨 조회, 예약, 대중교통은 이번 고도화 범위에서 제외했다. 테스트 482개 통과, 12개 건너뜀, 타입 검사와 프로덕션 빌드 통과.

## 현재 지원 계약

- 국내 장소 공급자에서 찾을 수 있는 당일 데이트·당일치기·최대 2박 3일의 현지 코스를 대상으로 한다. 3박 이상 요청은 2박으로 조용히 줄이지 않는다.
- 숙박 여행은 관광·식사 중심의 **현지 코스**다. 숙소 예약, 출발지 왕복편, 숙소 전후 이동, 대중교통 환승과 입장 가능 여부까지 확인된 여행 상품이 아니다. 도보를 명시한 여행은 일자별 보행 경로가 응답한 경우 그 실제 거리를 비교하며, 조회 실패 시 직선거리 추정이라고 표시한다.
- 날짜·지역·이동수단·도착/출발 시각이 없으면 확인되지 않은 조건을 확정 사실로 말하지 않는다. 명시한 현지 도착/출발 시각만 첫날/마지막 날 시간창에 반영한다.
- 사용자 필수 장소, 금지 장소, 순서, 수정 시 기존 장소와 일차는 장소 품질 점수보다 우선한다.

## 평가 케이스와 채점

| 유형 | 대표 입력 | 핵심 합격 조건 |
| --- | --- | --- |
| 저녁 데이트 | 식사 → 분위기 좋은 카페 → 공연 | 메뉴·공간 근거, 공연 회차와 시간, 실제 보행 경로 |
| 취향 충돌 | 한 명은 한식, 다른 한 명은 조용한 공간 | 두 사람 조건을 설명하고 대안 비교 |
| 장소 수정 | 2일차 카페만 바꾸기 | 다른 날의 장소·순서·시간 불변 |

| 1박 2일 | 군산·전주·경주, 관광과 지역 음식 | 날마다 근거 있는 핵심 경험과 식사, 경험 차이, 실현 가능한 시간 |

각 실제 요청은 `요청 해석 → 후보 수 → 지점별 근거 수·등급 → 날짜/운영 사실 → 하드 제약 → 이동 근거 → 날짜별 경험 → 응답 시간·비용 → 사람 평가`를 한 묶음으로 기록한다. 단위 테스트는 하드 제약을 검증하고, 라이브 평가는 실제 공급자 실패율과 선택 품질을 측정한다. 사람 평가는 장소명을 가린 두 코스를 블라인드 비교해 방문 의향·요청 적합성·실행 가능성을 따로 채점한다.

## 2026-09-25 첫 지역 기준선

`LIVE_TRIP_REGIONS=1 npx vitest run src/lib/openai/tripRegional.live.test.ts`로 군산·전주·경주 1박 2일 현지 코스의 결정적 대안을 실제 장소 API로 조회했다. 각 지역 67~70개 후보에서 공식 설명이 붙은 관광지 14~15곳이 있었고, 수정 후 세 지역 모두 두 날의 핵심 장소 근거·식사·장소 수 제약을 통과했다. 선택 코스의 근거는 지역마다 **4곳 중 2곳**이었다. 전주는 첫 실행에서 2일차 관광 근거 누락으로 탈락했고, 근거 있는 날짜별 핵심 장소를 우선하도록 바꾼 뒤 통과했다. 어린이 전용 놀이터가 관광 후보로 선택된 사례도 필터를 추가했다.

이 수치는 **세 지역의 단일 시점·단일 요청**에 대한 결정적 코스 검사다. 모델 실행 안정성, 실제 교통·영업·가격, 숙소, 사용자 선호 점수나 95% 성공률을 입증하지 않는다.

같은 날 군산의 OpenAI 포함 전체 파이프라인을 한 번 실행했다. 75개 후보에서 네 장소 모두 지점별 근거가 있는 `자천대 → 군산떡갈비`, `근대건축관 → 싹싹브리또` 코스가 나왔다. 모델 대안 3개를 비교했고 약 23초가 걸렸다. 이 실행은 성공 사례 한 건이며, 다른 지역의 모델 성공률이나 P95 지연을 입증하지 않는다. 이 요청의 이동수단은 대중교통이어서 경로는 직선거리 기반이었다.
